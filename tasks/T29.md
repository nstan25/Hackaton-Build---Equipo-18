> **Pedido del humano (29/10):** Railway avisa que Config as Code (`railway.json`) deja de leerse el **1/12/2026**. Migrar al formato nuevo, para los entornos **production** y **dev** (proyecto `hopeful-cooperation`, servicio `bcs`). El archivo nuevo va a ir a las ramas `main` y `dev`.

## Objetivo
1. Generar el archivo de IaC con `railway config migrate` (primero en seco, `--show`). Elegí el lenguaje que la CLI pueda **planificar sin instalar runtimes nuevos**: en la VM **no hay node ni chromium**; si `ts` necesita node, probá `py` (hay Python) o `go`; si cualquiera necesita un paquete o runtime nuevo, `ask` antes.
2. **Variables no gestionadas** (`--variables unmanaged`): `BCS_APP_TOKEN`, `OPENAI_API_KEY`, `BCS_SCALE` siguen solo en Railway. **Ningún secreto en el archivo ni en el repo**; no imprimas valores.
3. Que el archivo describa lo que hoy define `railway.json` (Dockerfile, healthcheck `/health` 120 s, reinicio ON_FAILURE ×5, 1 réplica, **Serverless/sleep**, watch patterns) para **los dos entornos**, sin cambiar dominios, volúmenes ni variables. Si la herramienta quiere tomar control de recursos que hoy no maneja `railway.json` (volúmenes, dominios), dejalos fuera o documentá por qué.
4. Correr `railway config plan` contra **production** y **dev** y guardar la salida (sin secretos) en `~/bcs-shared/runs/T29/`. El plan tiene que dar **sin cambios** (o solo cambios de forma, explicados). **Prohibido** correr `railway config apply`, `railway config migrate cutover`, `railway up`, `railway redeploy` o cualquier cosa que cambie Railway: eso lo hace el orquestador después de revisar.
5. Documentar en `docs/infra/railway-iac.md`: qué cambia, cómo hacer el cutover (primero dev, después production), cómo verificarlo (`railway config migrate status`, un deploy, `/health`, Serverless), cómo deshacerlo (`railway config migrate undo`) y cuándo borrar `railway.json` (solo después del cutover de los dos entornos).
6. Si encontrás que la rama `dev` o el entorno dev necesitan algo distinto (p. ej. otra rama de origen), dejalo explicado.
